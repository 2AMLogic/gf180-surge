DECISION FORCED BY THIS MEASUREMENT: a matcher on
"$readmemh(...): Not enough words" would flip THIS run — verdict PASS,
integer-exact over 4125 blocks — to FAIL, on all five files at once. It is
not a candidate mechanism at any threshold, for any subset of the memories,
and no amount of tightening the pattern can help, because the warning is
emitted by the healthy case for exactly the same reason as by the truncated
one (the TB's memory declarations are far larger than any real stimulus).
Truncation is therefore detected by a CONTENT check against the model side's
own declared length, NOT by reading simulator output. Recorded per the
issue's "record the decision either way".

6. WHAT IS NOT ESTABLISHED HERE
--------------------------------
- reports/sxt-026/artifacts/rtl-exactness.txt is NOT regenerated or re-graded
  by this change. Section 1/4's run is a fresh run of the same fixture on this
  host, recorded as evidence about the harness, not as a new exactness claim.
- Steps 1-5 of tools/run_sxt026_checks.py (asset-manifest compile, NC-A/NC-B
  model controls, budget metrics) were NOT run: they need oracle *renders*,
  which need more of the pinned tree than this host has (section 0). Status
  NOT_RUN, which is not a pass.
- A run dir carrying no rtl/stimulus_index.json (produced by tooling older
  than this change) gets NO truncation check. That is reported in the summary
  as stimulus_lengths.status=NOT_RUN with the reason, never as a pass, and
  never as a failure — failing it closed would turn every such healthy run
  into a FAIL, which is the false-positive outcome this issue exists to
  avoid.
