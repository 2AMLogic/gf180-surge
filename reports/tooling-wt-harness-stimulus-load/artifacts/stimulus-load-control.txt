7. THE COMMITTED-PASS RE-RUN IS NOT_RUN (NOT a pass)
-----------------------------------------------------
reports/sxt-026/artifacts/rtl-exactness.txt (fixture kick-wtfix-kt /
seq-wt-pitch-extremes-hi-v1) was NOT re-run: its stimulus is derived at run
time from the external pinned asset tree, which is never committed
(decision-records/0004) and is absent on this host. Status: NOT_RUN. No
committed artifact was regenerated or re-graded by this change.

What can be said without re-running it:
  * On a run where the stimulus loaded and vvp exited 0, sim_fails is empty
    (section 3, control 4 — measured, including the absence of any
    'ERROR:' line on a real healthy-load stdout). With sim_fails empty the
    comparison, the traffic reconciliation, `checked`, `mismatches`,
    `first_failures`, `verdict` and both exit paths (base and --mutant) are
    computed exactly as before; the summary gains two keys
    (`comparison`, `sim_stdout_tail`) and loses none.
  * The `--mutant` leg still requires cmp_fails AND a simulator that ran, so a
    stimulus that never loaded cannot be reported as a passing negative
    control; it now exits non-zero for a named reason instead of an unnamed
    one.
  * Issue #188's stop/escalate condition (a committed transcript produced by a
    run with a missing stimulus file) was NOT triggered: pre-fix such a run
    printed `mismatches=3, first_failures[0]='... missing T line'` and exited
    non-zero (section 1, control 1), so it could not have been recorded as a
    PASS. This is an argument about the pre-fix code's reachable paths, not a
    re-execution of the fixture.


8. BOUNDED FINDING recorded, not fixed (filed separately)
----------------------------------------------------------
A TRUNCATED (as opposed to absent/unopenable) stimulus file is NOT detected by
this change. Icarus reports it as

  WARNING: .../tb_wavetable.sv:279: $readmemh(rtl/ctrl.hex): Not enough words
  in the file for the requested range [0:262143].

— a WARNING about length, not an open failure, and one that a healthy run is
expected to emit: `ctrl_mem` alone is declared [0:262143] while real ctrl.hex
holds a few words per block. Matching it would flip genuinely passing runs to
FAIL, so it is deliberately NOT matched, and the pre-fix-quality baseline
needed to decide the question (what warnings a healthy pinned-tree run emits)
requires the external asset tree: NOT measurable here. Filed as its own issue
rather than guessed at.

The shared helper tools/_rtl_compile_common.py::compile_and_run (check=True
throughout) has the same blind spot and is imported by 11 harnesses, none of
them this one; enumerated and filed separately — see EVIDENCE.md §"Scope
decision".
