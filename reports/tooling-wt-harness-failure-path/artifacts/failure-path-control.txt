4. THE COMMITTED-PASS RE-RUN IS NOT_RUN (NOT a pass)
----------------------------------------------------
The issue's regression leg ("re-run the harness against an existing
committed-PASS case and confirm the verdict is unchanged") targets
reports/sxt-026/artifacts/rtl-exactness.txt (fixture kick-wtfix-kt /
seq-wt-pitch-extremes-hi-v1, 4125 blocks). It could NOT be executed here:

  $ python3 model/oscillators/wavetable/run_model.py --inputs \
      model/oscillators/wavetable/inputs/kick-wtfix-kt.json --sequence \
      seq-wt-pitch-extremes-hi-v1 --out-dir /tmp/wt182-kt --rtl
  FileNotFoundError: [Errno 2] No such file or directory:
  '/Users/joseph/dev/surge-xt-oracle/surge/resources/data/wavetables/Basic/
  Triangle.wt'

The stimulus (rtl/wt_table.hex) is derived at run time from the external
pinned asset tree, which is never committed (decision-records/0004) and is not
present on this host. Status for that leg: NOT_RUN. It is NOT reported as a
pass and no committed artifact was regenerated by this change.

What CAN be established about the committed transcripts without re-running
them, from the pre-fix control code itself:

  * Pre-fix, `main()` reached ANY printed verdict only when
    `run.returncode == 0` — a non-zero return raised UnboundLocalError before
    the summary was built (control 1). Every committed transcript therefore
    records a run whose simulator exited 0, i.e. a run on which the new
    `sim_fails` list is empty.
  * With `sim_fails` empty, `fails == cmp_fails`, which is exactly the
    pre-fix binding; `verdict`, `mismatches`, `first_failures` and both exit
    paths (base and --mutant) are then bit-identical to pre-fix behavior.
  * Consequently the issue's stop/escalate condition ("a committed PASS was
    resting on a discarded failure") cannot have been triggered by this
    change: no committed transcript can have hidden a simulator failure,
    because the pre-fix code could not have printed a verdict at all if the
    simulator had failed.

This is an argument about the reachable paths of the pre-fix code, not a
re-execution of the fixture. Re-running the SXT-026 exactness leg on a host
with the pinned asset tree remains outstanding and is unaffected by this fix.
