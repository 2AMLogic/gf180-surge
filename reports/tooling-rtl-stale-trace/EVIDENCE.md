# Tooling evidence: invocation-owned RTL traces in reporting mode (issue #360)

Scope: tool failure reporting in the shared RTL simulator helper
`tools/_rtl_compile_common.py`. No DSP, RTL, model, budget or comparison-rule
change. Nothing here bears on Surge fidelity, preset support, listening
quality, FPGA/gf180mcu synthesis or hardware playback.

## Behavior change

`compile_and_run(..., report_sim_fails=True)` with a non-null `trace_name`:

- deletes the helper-owned `workdir/trace_name` before `vvp` launches
  (after the declared-input and compile checks), so a file at that path
  afterward can only be this invocation's output;
- after a clean run (no compile, timeout, non-zero-exit or `$readmemh` failure)
  requires that file to exist; absence becomes the single `sim_fails` entry
  `missing current-run output: <trace_name> (...)` and `SimResult.trace` is
  `None`. Callers' existing `comparison: NOT_RUN` branch handles it; no
  caller was edited;
- refuses a `trace_name` that resolves outside the run dir, so deletion
  never reaches a path the helper does not own.

Unchanged: `trace_name=None` (`tools/compare_control_rtl.py`; no trace
declared, nothing deleted, no missing-output failure), the non-reporting
default path, and `tools/compare_sine_rtl_model.py --trace` offline reuse
(that branch never calls the helper). Helper sha256 before
`58912168e1f0f75eb92d53d50bf2cfcd86939ec91d5d42f88fa007442d52e850`, after
`871d7d260b0a95f885cbf145db9a9d76d31d2bddc23f2602192d493867b76b3a`.
`tools/_rtl_compile_common.py` is not in `docs/byte-frozen-sources.json`.

invocation's trace, so no caller-level contract conflict was found.
